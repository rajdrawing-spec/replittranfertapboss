We currently have a Targetgum Marketing Workspace inside TapBoss.

19. SECURITY
==================================================

Implement server-side RBAC and tenant isolation.

Never trust:

company_id
brand_id
project_id

sent from frontend.

Always resolve authorized projects from authenticated user permissions.

Every database query must apply tenant/project filtering.

Example conceptual query:

WHERE marketing_project_id IN (
    SELECT project_id
    FROM user_project_access
    WHERE user_id = authenticated_user.id
)

Do not use unrestricted:

SELECT * FROM campaigns

for client endpoints.

Create centralized authorization middleware:

requireAuth()
requireRole()
requireCompanyAccess()
requireProjectAccess()
requireClientVisibility()

The key architecture
                    TAPASHUB
                       │
             ┌─────────┴─────────┐
             │                   │
        INTERNAL TEAM        CLIENT USERS
             │                   │
      Targetgum Workspace   Client Marketing Portal
             │                   │
       ALL CLIENTS          ONLY ASSIGNED PROJECT
             │                   │
     ┌───────┼───────┐          │
   Client A Client B Client C   Client A
                               ONLY

This is the important separation that prevents the "why can this client see another company's information?" problem you were concerned about earlier.

I would also make marketing_project_id the primary security boundary, rather than just company_id, because one company can eventually have multiple brands, campaigns, or marketing projects.
