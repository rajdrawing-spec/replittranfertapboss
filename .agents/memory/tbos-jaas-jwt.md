---
name: TBOS JaaS JWT integration
description: How Jitsi as a Service (JaaS) JWTs are signed and what payload 8x8/JaaS requires.
---

JaaS requires a signed JWT to join a room. The JWT is generated by the backend when a meeting is created.

**Format of the JaaS magic cookie secret:**
`vpaas-magic-cookie-<apiKey>/<appId>` stored as `JITSIAAS_MAGIC_COOKIE`.

**JWT algorithm:**
- Algorithm: HS256
- Key: `Buffer.from(apiKey, "hex")` (the apiKey is a hex string)
- Payload must include a `context` object with a `user` sub-object; without it JaaS returns “Authentication failed: The 'context' object is missing from the payload.”

**Payload structure:**
```json
{
  "aud": "jitsi",
  "iss": "<appId>",
  "sub": "<appId>",
  "room": "<roomName>",
  "exp": <unixTimestamp>,
  "context": {
    "user": {
      "name": "<displayName>",
      "email": "<email>",
      "avatar": "<avatarUrl>",
      "moderator": true
    },
    "features": {
      "livestreaming": true,
      "recording": true,
      "transcription": true,
      "outbound-call": true,
      "sip-outbound-call": true
    }
  }
}
```

**Room URL format:**
`https://8x8.vc/<appId>/<roomName>?jwt=<token>`

**Frontend SDK configuration:**
For JaaS, the serverUrl is `https://8x8.vc/<appId>`. The frontend Jitsi SDK must be configured with:
- `domain`: `8x8.vc`
- `roomName`: `<appId>/<roomName>`
- `jwt`: the token

**Why this matters:** JaaS is stricter than public Jitsi. The JWT must be signed correctly and contain the `context` payload or all participants will be rejected with the authentication-failed error.
